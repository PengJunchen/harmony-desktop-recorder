# 清录：鸿蒙电脑应用市场上架准备

核对日期：2026-10-29。下方差距分析以 `e4a2f98`（0.1.2）为基线。0.2.0 已补充版本化隐私同意、政策与联系入口、撤回同意、录像删除与诊断清理，并生成 release 模式的未签名 APP；正式发布证书、发布 Profile、市场预检与审核尚未完成。当前送审材料见 [MARKET_LISTING.md](MARKET_LISTING.md)。本文不表示应用已经通过审核。

## 结论

**适合评估以本人实名开发者账号，将清录作为本地录屏工具走华为应用市场的公开发行流程；现有绑定设备的 debug 签名不能直接作为市场发布签名使用。** 官方《账号服务与权限》将实名个人开发者的“证书”“Profile”“应用上架”“应用测试”均列为支持，因此“个人账号”本身不是一般上架权限的障碍。具体工具类目、电脑端设备范围及所需资质，仍须在本人账号的发布页面确认。[账号服务与权限](https://developer.huawei.com/consumer/cn/doc/app/hdc-services-and-benefits-0000002723168012)

华为为鸿蒙电脑提供了应用市场分发入口；发布后的用户从市场获取应用，而不是领取开发者的设备调试证书。能编译、能用公开录屏 API、能在一台电脑录制，都不能单独证明一定通过市场审核。[鸿蒙电脑开发入门](https://developer.huawei.com/consumer/cn/multidevice/pc/get-started/)、[在应用市场分发](https://developer.huawei.com/consumer/cn/appgallery/devstart/)

## 账号、证书与包格式

| 项目 | 当前状态 / 应采用的方式 |
| --- | --- |
| 开发者主体 | 可以评估使用本人实名个人开发者账号；发布应用权属必须真实 |
| 本机现有签名 | 已用项目校验脚本核实，Profile 类型为 `debug`，属于指定设备的开发调试用途 |
| 市场签名 | 使用正式发布身份、应用发布证书与匹配的发布 Profile；按当前 DevEco 发布向导采用可用的自管或云管理签名流程，不能拿 debug Profile 顶替 |
| GitHub 0.1.2 附件 | release 构建模式的未签名 HAP，不是已签名的应用市场提交包 |
| 市场提交文件 | 按 HarmonyOS 发布流程生成 `APP` 应用发布包，不能只把 `.hap` 扩展名改成 `.app` |

个人 / 企业表示开发者主体，debug / release 表示签名使用目的，`buildMode=release` 表示编译模式，三者需要分别核对。华为调试 Profile 文档明确选择调试证书和调试设备；官方提交页明确要求完成开发后打包为 APP，通过开发者中心上架。[调试 Profile](https://developer.huawei.com/consumer/cn/doc/doccenter-getting-started/agc-help-debug-profile-0000002248181278)、[提交你的应用](https://developer.huawei.com/consumer/cn/app/submit)、[发布应用配置](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/ide-publish-app)

官方《申请发布证书》明确要求发布阶段使用发布证书与发布 Profile 重新签名；《应用审核指南》3.8 要求发布版本关闭调试。因此当前已验证为 `debug` 的 Profile 需要替换，不能靠切换编译模式解决。[申请发布证书](https://developer.huawei.com/consumer/cn/doc/app/agc-help-release-cert-0000002283336729)、[审核指南](https://developer.huawei.com/consumer/cn/doc/app/50104)

发布密钥、证书和 Profile 应保留在受控开发环境，不进入公开仓库或公开附件。开始正式发行前固定包名与签名身份，后续升级沿用正确的发布链路；debug 安装版到市场版的覆盖与数据迁移要另行验证，不能保证直接覆盖保留录像。

## 建议执行流程

1. **核实主体与类目。** 登录 HarmonyOS 开发者中心，确认个人实名状态与应用上架权限；为清录创建或关联应用，确认应用名称、`com.personal.desktoprecorder` 包名及 APP ID 的权属，选择符合实际功能的工具类目，配置电脑设备。不要借用他人证书或以他人主体发布。[分发入门](https://developer.huawei.com/consumer/cn/appgallery/devstart/)
2. **先确认资质边界。** 在该应用、地区及类目的资质页面核对需提交的证明材料。中国大陆的 APP 备案、离线工具的适用说明、是否要求软著或其他版权材料，依平台实际要求办理；不要因源码公开或免费而自行认定全部豁免。[应用资质审核要求](https://developer.huawei.com/consumer/cn/doc/app/80301)、[APP 核准（备案）指引](https://developer.huawei.com/consumer/cn/doc/app/50130)
3. **准备产品与隐私材料。** 完成应用图标、真实电脑截图、功能说明、支持设备 / 系统范围、开发者服务与审核联系方式，并准备能访问的隐私声明，准确说明画面、系统声音、可选麦克风、本地录像及诊断日志如何处理。[提交你的应用](https://developer.huawei.com/consumer/cn/app/submit)、[配置隐私声明入口](https://developer.huawei.com/consumer/cn/appgallery/devstart/)
4. **补齐上架所需的产品行为。** 见下一节。保留系统授权与受保护内容限制，不增加静默录制、绕过系统授权、伪造隐私授权等行为。
5. **建立正式发布签名并打 APP。** 在当前 DevEco / 开发者中心的发布流程中建立匹配的发布身份与 Profile，选择 release 构建，使用 Build APP(s) / 相应发布向导生成市场包；核对包名、版本号、签名用途、`debug=false` 与设备类型。[提交你的应用](https://developer.huawei.com/consumer/cn/app/submit)、[DevEco 发布应用](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/ide-publish-app)
6. **完成预检与电脑实测。** 进行隐私、安全、稳定性、兼容性与性能检查，并重点验证首次 / 拒绝授权、系统停止录屏、麦克风拒绝、最小化、窗口缩放、磁盘不足、长时间录制、导出与卸载数据行为。华为提供本地 DevEco Testing 及云测试的上架预检能力，实际电脑机型覆盖应以工具支持情况为准。[测试服务入门](https://developer.huawei.com/consumer/cn/testing/get-started/)
7. **上传与提交审核。** 上传软件包并通过基础合法检测，配置国家 / 地区、设备、免费情况、隐私声明、隐私标签、资质及审核说明；按发布页面确认后提交，依据实际审核意见整改。通过后从市场下载并验证安装 / 升级及录制。[分发入门](https://developer.huawei.com/consumer/cn/appgallery/devstart/)

## 当前工程的适合之处与差距

以下“当前事实”依据项目源码及本机包检查；“建议”是针对清录的工程判断，不将建议全部包装成市场明文硬性条款。

| 当前事实 | 对上架准备的影响 / 建议 |
| --- | --- |
| 只声明 `2in1` 与麦克风权限，没有声明 INTERNET，依赖清单为空 | 本地工具路线较简单；仍需如实声明屏幕、音频及日志处理，不能只写“没有网络，所以没有隐私问题” |
| 使用系统 `AVScreenCaptureRecorder`，开始录制由用户点击并经系统授权，等待系统开始状态 | 应保留该交互，不承诺录制被系统保护的画面；公开 API 的存在不等于该应用已取得审核许可 |
| 用户选用麦克风时才申请麦克风权限 | 申请时机符合按功能触发的方向；需验证拒绝后可继续不含麦克风的录屏，不反复强制索权 |
| 当前界面只有“本地录制 · 无上传”等提示，未找到完整隐私政策、关于、客服 / 版本入口 | 审核 7.1 明确要求平台及应用内都提供便捷可查看的隐私政策链接，7.3 要求说明用户权利与隐私投诉渠道；缺应用内隐私入口属于明确上架差距。版本 / 关于页则是便于完善这些入口的工程方案 |
| 录像在应用沙箱保存，列表有播放和导出，未提供单条删除入口 | 建议补充删除 / 清理及容量提示，明确卸载清数据、导出后由用户管理，方便用户控制本地录像 |
| 私有目录诊断日志记录系统版本、分辨率、状态及错误，并按大小轮转 | 隐私声明应如实说明本地诊断信息与保留机制；不要描述为“应用完全不处理任何信息” |
| 编译 SDK 26.0.0，但兼容 / target SDK 为 `6.1.1(24)` | 编译使用 SDK 26 不等于 target 已为 26；提交前核对当前市场的电脑端 target API 门槛，不凭版本号猜测达标 |
| 没有长时后台任务声明或申请 | 最小化后持续录屏、特别是使用麦克风时，需要对照当前 PC/2in1 规则和真机行为验证。不能直接照搬手机的后台规则，也不能在未验证前承诺无限后台录制 |
| 已有本机录制与自动化验证，但尚无市场包预检结果 | 现有结果是开发验证；还需要实际 APP 包的合法检测、隐私 / 兼容性预检和市场安装验证 |

源码定位：`entry/src/main/module.json5`；`RecorderService.ets` 的麦克风申请、录屏创建与启动、诊断写入；`Index.ets` 的提示和录像行；`build-profile.template.json5` 的 SDK 配置。系统权限申请应避免强制、频繁、过度索权，华为应用市场官方已有专题指引。[应用市场官方权限申请指南](https://developer.huawei.com/consumer/cn/forum/topic/0204191845762063065)

正式审核条款还明确：7.5 在处理个人信息前需明示规则并取得自愿、明确同意，7.6 提供便捷的撤回方式，7.17–7.19 要求按业务场景动态、最小化索权并同步解释敏感权限用途。对于清录，录屏授权、麦克风授权、应用自己的隐私告知需要形成一致的完整流程。[审核指南 7.1–7.6、7.17–7.19](https://developer.huawei.com/consumer/cn/doc/app/50104)

若暂时没有隐私政策网站，官方隐私声明托管服务明确覆盖发布地区包含中国大陆、设备为手机 / 平板 / PC/2in1 的 HarmonyOS 应用，可评估使用平台模板托管；内容仍须反映清录真实行为。[配置隐私声明](https://developer.huawei.com/consumer/cn/doc/app/agc-help-release-app-privacy-state-0000002278878296)

没有账号体系的本地工具，不应为满足并不适用的账号注销流程而强行新增登录。是否需要某种特定弹窗、某项版权材料以及具体展示方式，应按当前审核规则、应用实际处理行为和审核意见确定。

## 备案、软著及政策确认边界

- **个人实名的一般上架权限：已确认。** 官方权限表列出支持个人的应用上架、测试、证书与 Profile；这不等于任何类目或特殊业务自动获准。[账号服务与权限](https://developer.huawei.com/consumer/cn/doc/app/hdc-services-and-benefits-0000002723168012)
- **清录的免费电脑录屏工具类目：待本人后台确认。** 本次没有发现录屏工具一概禁止个人上架的官方条款，也没有取得针对清录的类目确认或审核结论，因此不写“保证可上架”。
- **离线工具备案：存在需要进一步确认的单机适用路径。** 官方社区精选答复提到审核会检查联网情况，断网不影响功能的单机应用与依赖联网的应用有所区别；但该答复不是本应用的备案豁免决定。清录应提交真实的纯本地功能说明，按当前正式备案指引和发布页面确认，不自行编造备案号，也不因没有服务器就判定所有场景免备案。[官方答开发者问第 19 期](https://developer.huawei.com/consumer/cn/forum/topic/0203203882289530006)、[APP 备案指引](https://developer.huawei.com/consumer/cn/doc/app/50130)
- **软件著作权：官方明确 APP 软件著作权证书为非必选资质，建议申请相关证书保护知识产权。** 不能把它说成清录必然必须先取得的条件，也不能因此忽略真实权属、第三方素材授权或具体业务资质。该规则另列个人开发者承诺函模板，应按本人主体与发布页面准备。[应用资质审核要求](https://developer.huawei.com/consumer/cn/doc/app/80301)
- **目标 API 与后台采集：待核对当前市场和 PC 文档。** 本次未取得一条适用于所有 PC 录屏工具的统一 API 26 门槛，也未取得清录最小化麦克风采集的审核结论。不得以手机要求或编译 SDK 推断电脑规则。

## 是否违反鸿蒙要求

按现有事实，**不能认定“本人实名账号开发并上架一个经用户授权的本地录屏工具”本身违规**；推荐把它作为常规工具申请发行资格、完成正式签名与隐私 / 质量准备。反之，用当前 debug Profile 冒充市场正式签名、引导普通用户以调试安装替代长期正式发行、绕过录屏授权或宣称可采集全部受保护内容，都不应作为上架方案。

还有一项重要的实用价值与成熟度审核风险：3.4 要求主功能完整正常，3.5 要求实质功能、价值与创意，并排除简单包装等情形；其举例原文还提到手机系统自带的简易功能。该措辞不能直接推导出“电脑录屏一概禁止”，但清录应证明自身的实质用户价值。可在审核说明中真实展示分辨率、自定义码率 / 体积预估、系统声音与讲解、录像管理和导出形成的闭环；这些是否构成足够差异与质量，仍由审核判断，不能保证通过。[审核指南 3.4–3.8](https://developer.huawei.com/consumer/cn/doc/app/50104)

最终是否合适取决于实际的账号和类目开放情况、合规材料、正式包预检与审核结果。建议先解决签名、隐私说明、录像清理及预检这几项，再进入提交审核阶段；本说明不代替平台审核结论。
